# 开发与 AI 协作记录

本文件记录本次开发的真实决策，用于后续整理实验报告。不是已经完成的实验报告，也不代替本人对核心代码的理解。

## 用户实际提出的要求

- “这个实时交互可以和粒子动画联合起来吗”
- “那我们做这个项目吧”
- “我觉得我们可以先讨论下具体方案”
- “我觉得应该主要做的是自由模式”
- “我觉得作品粒子化和进阶效果可以”
- “我们先把最基础的做好吧”
- “前端后端啥的怎么分啊？”

范围因此确定为先实现自由绘画与真实识别，作品粒子化和标准图案变形后续补充。个人署名使用用户提供的信息。

## 实际实现决策

1. 首先检查当前环境。NumPy 已有，PyTorch 未安装。基础版选用 NumPy 实现的轻量 MLP，减少额外依赖；不把它称为 CNN。
2. 从 Google 官方 QuickDraw 下载 12 类各 2400 条已被原游戏识别的笔画记录。固定随机种子，先划分原始画作，再只对训练集增加部分笔画样本。
3. 初始方案为浏览器推理。用户询问前后端分工后，增加本地 Python API，保留静态网页可使用的 Web Worker 推理，两种方式共用权重。
4. 预测请求只包含笔画，不传类别答案。对旧请求加版本号，防止清空、撤销后迟到的结果覆盖新画作。
5. 先实现自由绘画、前三名、确认、撤销、清空和 PNG 保存，未提前加入粒子动画。

## 本次发现和修正的问题

- PNG 导出最初按正方形处理，会裁掉宽画板左右的内容。改为保持画板长宽比，并单独留出署名区域。
- 响应式画板如果改变长宽比，可能裁掉已有笔迹。不同屏幕采用一致的画板比例，绘画坐标与屏幕像素分离。
- 将 Python 与 JavaScript 预处理分别实现后，加入真实测试样本的一致性测试，确认栅格图与概率输出一致，而不是只依赖肉眼观察。

## 后续更新：作品粒子化

用户确认加入作品粒子化。新增独立动画画布，确认猜中后沿原笔画按弧长采样、散开、聚拢。保留继续绘画、重播、清空和导出功能；不改模型和识别输入。对分离笔画的空白、粒子数量上限和原始输入不变性加入测试。标准图案变形仍未实现。


## 彩色标准图案

为 12 类物品添加 Canvas 绘制的独立标准图案及配色。按目标图案的像素颜色生成粒子，先从用户笔画散开，再平滑插值到目标图案。原笔画保持不变，继续画时恢复。保留类别专属语句和减少动态效果支持。此次仅发布预览网站，按用户要求不更新 GitHub。
